# 到梦空间 学分批量颁发脚本

用 Windows 电脑 + 一根数据线（或无线调试）驱动安卓手机上的「到梦空间」APP，按 Excel 名单把活动学分批量发给学生。适合活动负责人做「几十人到几百人发分」这种重复劳动。

- **输入**：录取名单 + 各分值的发分名单 +（可选）账号表 / 易班映射表 / 额外名单
- **过程**：名单校验 → 自动登录 → 搜索活动 → 进「学分管理」→ 按分值逐个搜学号 → 核对姓名 → 点「颁发 1 人」→ 读 APP 提示确认
- **输出**：一份带状态的结果 Excel + 完整日志；中途失败可以断点续跑

> 本文档按当前 `main` 分支（`d303b00`）的源码写成，只讲 Windows。所有行为都能在源码里对上，没有的部分（比如自动化测试、requirements.txt）本项目确实没有。

> ⚠️ **先看第 9 节「安全与合规」**：脚本会用你配置的账号在真实 APP 上批量操作，并且任务失败时账号密码会**明文**留在输出目录的 `config.json` 里。

## 1. 环境准备

### 1.1 Python

- Python **3.9 或更高**（代码用了 `list[str]`、`dict[float, Path]` 这类泛型注解），建议 3.11 / 3.12
- 安装时勾选 **Add python.exe to PATH**，否则后面 `python` 命令找不到
- 验证：

```bat
python --version
```

### 1.2 安装依赖

仓库里**没有** `requirements.txt`，需要装的就这 4 个：

```bat
pip install pandas openpyxl rich uiautomator2
```

| 包 | 用途 |
|---|---|
| `pandas` | 读 Excel、名单比对 |
| `openpyxl` | pandas 读写 `.xlsx` 的引擎 |
| `rich` | 终端进度条、表格、彩色日志 |
| `uiautomator2` | 安卓 UI 自动化（会自动带上 `adbutils`） |

验证：

```bat
python -c "import pandas, openpyxl, rich, uiautomator2; print('ok')"
```

> 建议用虚拟环境隔离：`python -m venv .venv` 然后 `.venv\Scripts\activate`，再执行上面的 `pip install`。

### 1.3 准备 ADB（最容易踩的坑）

脚本把 ADB 路径**写死**了，取的是 `daomeng\platform-tools\adb.exe`（见 `daomeng/cli.py`），文件不存在就直接报错退出。所以：

1. 下载 Google 官方 platform-tools：
   <https://dl.google.com/android/repository/platform-tools-latest-windows.zip>
2. 解压，把里面的 **`platform-tools` 整个文件夹**放到 `daomeng\` 目录下，最终结构必须是：

```
仓库根目录\
├─ DM.py
├─ README.md
└─ daomeng\
   ├─ cli.py
   ├─ device_controller.py
   ├─ file_manager.py
   ├─ selectors.py
   ├─ ...
   └─ platform-tools\          ← 放这里
      ├─ adb.exe               ← 必须叫这个名字
      ├─ AdbWinApi.dll
      ├─ AdbWinUsbApi.dll
      └─ ...
```

3. 不能改名、不能换位置（`daomeng/platform-tools/` 已经在 `.gitignore` 里，不会被误提交）
4. 验证：

```bat
daomeng\platform-tools\adb.exe version
```

### 1.4 手机准备

1. 手机装好「到梦空间」，并且用一个**对目标活动有管理/发分权限**的账号能正常登录
2. 打开开发者选项：设置 → 关于手机 → 连点「版本号」7 次
3. 打开 **USB 调试**。小米/红米还要打开 **USB 调试（安全设置）** 和 **USB 安装**；华为/荣耀、vivo、OPPO 通常还需要登录厂商账号才能开
4. 数据线连电脑，手机上弹「是否允许 USB 调试」→ 勾选「一律允许」→ 允许
5. 验证设备已连接（`adb devices` 里出现 `<序列号>  device`，**不能是** `unauthorized` 或 `offline`）：

```bat
daomeng\platform-tools\adb.exe devices
```

6. **首次使用**（或连接老是失败时）要在命令里加 `-i`，它会把设备端服务装到手机上：

```bat
python DM.py -i -f "D:\名单\录取名单.xlsx" 0 -f "D:\名单\发分名单.xlsx" 0.5 -u "D:\名单\账号.xlsx"
```

> ⚠️ **`-i` 不是「只初始化」模式**：它是「先初始化设备端服务，再照常跑完整流程」，所以你要在**正式要跑的那条命令**上加 `-i`，而不是单独跑一条命令就以为初始化完了。
>
> 如果你只想初始化、不想发分，可以手动执行（注意让 adbutils 找到我们放的那个 adb）：
>
> ```bat
> set ADBUTILS_ADB_PATH=%CD%\daomeng\platform-tools\adb.exe
> python -m uiautomator2 init
> ```

### 1.5 手机设置建议

- **保持屏幕解锁**：脚本会调用 `unlock()` 唤醒并上滑解锁，但**解不开锁屏密码**，建议先把「息屏时间」调长，跑之前手动解锁
- **关掉该 APP 的电池优化 / 后台限制**，否则 uiautomator2 的设备端服务会被系统杀掉，跑到一半报连接失败
- **给 APP 通知权限**：脚本靠读 Toast 判断「是否真的发放成功」，读不到就只能标成「未知」，需要人工核对
- 关掉会弹窗打扰的应用（系统更新、清理助手之类），弹窗会挡住控件

## 2. 准备名单 Excel

一共涉及 5 种表，**只有录取名单和至少一份发分名单是必须的**。

> 所有 `-f` 名单文件，脚本**只读这 6 列**：`学号` `姓名` `院系` `专业` `班级` `易班ID`，其它列一律忽略。其中：
> `姓名` 必须有；`学号` 必须有（唯一例外见 [2.4](#24-易班导出-csv可选-yb)）；`院系`/`专业`/`班级` 缺了会自动补空列，不报错。

### 2.1 录取名单（必须，分值写 `0`）

**它的作用是「校验基准」**：发分名单里的每个学号，都要在这张表里找到一个**学号相同且姓名一致**的人，才会真的去发分；它自己不发分，也不会出现在结果表里。

要求：

- 必须有一列叫 **`活动名称`**，而且脚本读的是**这一列第二行数据**的值（源码是 `read_excel(..., usecols=["活动名称"], nrows=2).iloc[1, 0]`）
- 因此这个表**至少要有两行数据**，否则直接抛 `IndexError`
- `学号`、`姓名` 两列必须有；`院系`、`专业`、`班级` 有的话能帮脚本自动纠正错误学号（见 [4.1](#41-名单预处理阶段连手机之前)）；`易班ID` 配合 `-yb` 使用
- 学号必须是 **11 位纯数字**

> ⚠️ **这一格最容易填错**：活动名不是取第一行，而是取**第二行**。
> 这个值同时决定三件事：输出目录的名字、APP 里搜索哪个活动、结果 Excel 的文件名。填错就会报「未找到活动」。
>
> 如果你打开自己导出的文件，发现活动名其实在**第一行数据**里，那就是这里和你的文件对不上。两种处理方式：把整张表往下挪一行（让活动名落到第二行），或者把 `daomeng/cli.py` 里的 `iloc[1, 0]` 改成 `iloc[0, 0]`。

示例（`活动名称` 列的第一行数据脚本不读，填什么都行；第二行数据才是活动全名）：

| 活动名称 | 学号 | 姓名 | 院系 | 专业 | 班级 |
|---|---|---|---|---|---|
| （不读，随意） | | | | | |
| 2026 年春季运动会志愿服务 | 20231234567 | 张三 | 机械工程学院 | 机械电子工程 | 机电 2301 |
| | 20231234568 | 李四 | 机械工程学院 | 机械电子工程 | 机电 2301 |

### 2.2 发分名单（至少一份，分值大于 0）

- 用 `-f <路径> <分值>` 传入，**一份文件对应一个分值**，可以重复传多份
- 必须有 **`姓名`** 列
- 必须有 **`学号`** 列 —— **整个列都不存在会直接报错**：`文件 X 缺少学号列且未启用易班映射`。唯一例外是配合 `-yb` 使用（表里有 `易班ID` 列时学号列可省，见 [2.4](#24-易班导出-csv可选-yb)）
- 学号**单元格填错或留空**（不是 11 位数字）不会立刻丢弃：脚本会按姓名 + 班级去录取名单里智能匹配，匹配不唯一时会停下来问你怎么处理（见 [4.1](#41-名单预处理阶段连手机之前)）
- 分值不能重复（两份文件写同一个分值会直接报错），且必须有一份是 `0` 的录取名单

示例：

| 学号 | 姓名 | 班级 |
|---|---|---|
| 20231234567 | 张三 | 机电 2301 |
| 20231234568 | 李四 | 机电 2301 |

### 2.3 账号表（可选，`-u`）

- 两列：**`账号`**、**`密码`**
- ⚠️ 只读**第一条**记录（源码里是 `list(accounts.keys())[0]`，多账号还是 `TODO`）
- 不传 `-u` 也能跑：脚本遇到登录页会暂停，让你在手机上手动登录后按回车继续

| 账号 | 密码 |
|---|---|
| 13800000000 | your-password |

### 2.4 易班导出 CSV（可选，`-yb`）

- 三列：**`姓名`**、**`学号`**、**`易班ID`**
- 用途：发分名单里没有学号、只有姓名和易班ID 时，靠这张表反查学号
- **传了 `-yb` 之后，名单文件里没有 `学号` 列也可以**（前提是那张表有 `易班ID` 列），脚本会按 `易班ID` + `姓名` 反查学号 —— 这是 `学号` 列唯一的豁免情况
- 反查时要求 `姓名` 和映射表里**完全一致**；查不到的记录会被填上一个占位学号 `1000000000`，随后按「无效学号」进入交互式纠正流程（见 [4.1](#41-名单预处理阶段连手机之前)）
- 编码随便存（脚本会依次尝试 `utf-8` / `gbk` / `gb2312` / `gb18030` / `utf-8-sig`）

### 2.5 额外名单（可选，`-a`）

- 三列：`学号`、`姓名`、`分值`
- `分值` 可以写数字，也可以写 **`m`** / **`max`**（表示用本次所有分值里最大的那个），留空同样按最大分值处理
- 学号不在录取名单里的，会被记成 `未报名` 状态，**不会发分**
- 如果同一学号在普通名单里已经有记录，额外名单会覆盖它，并且取**较大**的分值

## 3. 运行

### 3.1 最小可跑命令

在仓库根目录（有 `DM.py` 的那层）：

```bat
cd /d D:\path\to\daomeng

python DM.py ^
  -f "D:\名单\录取名单.xlsx" 0 ^
  -f "D:\名单\发分名单.xlsx" 0.5 ^
  -u "D:\名单\账号.xlsx"
```

（`^` 是 cmd 的续行符；写成一行也行。路径含空格一定要加引号，`-f` 后面的分值**不加引号**。）

### 3.2 参数速查

| 参数 | 作用 | 说明 |
|---|---|---|
| `-f <路径> <分值>` | 一份名单 + 它对应的分值 | 可重复；**必须有一份分值为 0 的录取名单**；分值不能重复 |
| `-a <路径>` | 额外发放名单 | 列：`学号` `姓名` `分值` |
| `-u <路径>` | 账号表 | 列：`账号` `密码`；只取第一条 |
| `-yb <路径>` | 易班导出 CSV | 列：`姓名` `学号` `易班ID` |
| `-d <IP:端口>` | 连接指定的无线设备 | 不传则走 USB |
| `-p <IP:端口> <配对码>` | 先做无线调试配对 | 只有第一次需要 |
| `-i` | 初始化设备（装设备端服务），然后照常跑完流程 | 首次或连接异常时用；**不要和 `-d` 同时用**（见 6.3） |
| `-r <输出目录>` | 续跑上次失败的任务 | 不能再传 `-f` / `-a` / `-yb` |
| `--click-other-tab` | 搜索前先点「已获得其他学分」页签 | 个别活动需要 |
| `-cl <级别>` | 控制台日志级别 | 默认 `WARNING`，调试用 `DEBUG` |
| `-fl <级别>` | 文件日志级别 | 默认 `INFO` |

### 3.3 无线调试（可选，安卓 11+）

1. 手机和电脑连同一个 Wi-Fi，手机开发者选项 → **无线调试** → 打开
2. **第一次**要配对：手机点「使用配对码配对设备」，会显示一个 `IP:端口` 和 6 位配对码

```bat
python DM.py -p 192.168.1.23:37000 123456 -f "D:\名单\录取名单.xlsx" 0
```

3. 之后用**无线调试主页**显示的那个 `IP:端口`（**不是**配对用的端口）：

```bat
python DM.py -d 192.168.1.23:5555 -f "D:\名单\录取名单.xlsx" 0 -f "D:\名单\发分名单.xlsx" 0.5
```

> 也可以先手动 `daomeng\platform-tools\adb.exe connect 192.168.1.23:5555`，然后不加 `-d` 直接跑。

### 3.4 第一次跑建议

先用 **2~3 个人**的小名单 + 调试日志跑一遍，确认活动名、选择器、Toast 读取都正常：

```bat
python DM.py -cl DEBUG -fl DEBUG -f "D:\名单\测试-录取.xlsx" 0 -f "D:\名单\测试-发分.xlsx" 0.5 -u "D:\名单\账号.xlsx"
```

控制台会打印每一步在做什么（当前界面、点了什么、Toast 内容），日志文件也会记录全过程。

## 4. 运行过程中会问你什么

脚本不是全自动的，有两个阶段会停下来等你输入。

### 4.1 名单预处理阶段（连手机之前）

1. 读所有名单 → 从学号列里提取 **11 位学号** → 和录取名单交叉比对
2. 如果发现**无效学号**（不是 11 位、或者根本没填），会先打印一张对照表，然后问你：

```
请选择处理方式:
1. 全部拒绝
2. 仅智能选择
3. 智能选择，并手动输入无法确认的学号
请输入选项 (1/2/3) [3]:
```

- 默认是 **3**
- 「智能选择」的规则：先按**姓名**在录取名单里找，只匹配到 1 个人就自动采用；匹配到多个或 0 个时，再拿**班级**去比对，唯一命中就自动采用
- 选 3 时，剩下确认不了的会**逐条**问你：输入候选列表里的序号，或直接输入 11 位学号，输入 `0` 跳过

3. 如果发现**姓名不一致**（发分名单的学号在录取名单里存在，但姓名不同），会打印对照表并问你：

```
请选择处理方式:
1. 全部拒绝
2. 全部同意
3. 仅同意特定学生
4. 仅拒绝特定学生
请输入选项 (1/2/3/4) [2]:
```

- 默认是 **2（全部同意）**。同意表示「以**录取名单里的姓名**为准去发分」
- 选 3 / 4 时，按提示输入学生序号（逗号分隔）

4. 处理结果：
   - 通过的记录进入待发分队列，状态是 `未处理`
   - 被拒绝的记录也会进结果表，但**不会发分**，状态分别是 `学号错误（非11位有效学号）` / `姓名错误（或学号填写错误），录取表姓名XXX` / `未报名（或学号错误）`

### 4.2 设备阶段（连上手机之后）

- **登录**：传了 `-u` 就自动填账号密码并勾选协议登录；没传就暂停，让你在手机上登录好后按回车继续
- **导航**：自动走「我的 → 我的活动 → 管理 → 搜索活动名 → 学分管理 → 选分值 → 颁发」。找不到目标界面时会按返回键回退，**最多 25 次**，期间每 5 次会重启一次 APP；还是不行就暂停并提示：

```
多次返回无效，请手动操作至目标页后按回车继续
```

- **掉线**：自动重连；重连也失败时会问你：

```
设备连接失败，请选择重连方式:
输入新的 IP:端口 (如 192.168.1.100:5555)，留空使用有线连接，输入 'e' 退出
```

- 进度显示：一条总进度条 + 一条当前分值进度条，并显示正在处理的学生学号和姓名

## 5. 结果与断点续跑

### 5.1 输出目录

输出在 **`DM.py` 所在目录**（不是当前工作目录）下，名字是 `<活动名>-<时间戳>`，例如 `2026年春季运动会志愿服务-20260928-120000\`：

| 文件 | 什么时候有 | 说明 |
|---|---|---|
| `automation.log` | 始终 | 完整日志，**UTF-8** 编码（用 VS Code / Notepad++ 打开；cmd 里 `type` 可能乱码） |
| `<活动名>.xlsx` | 正常跑完 | 结果表 |
| `config.json` | 仅失败中断后 | 本次运行的完整配置，**含明文账号密码** |
| `students.db`（含 `-wal`/`-shm`） | 仅失败中断后 | 进度数据库 |

结果表的列：`学号` / `姓名` / `分值` / `状态` / `创建时间` / `更新时间`，按分值倒序。

> **任务成功结束时会自动删掉 `config.json` 和 `students.db`**，所以只有**失败中断后**才能续跑。

### 5.2 状态值含义

| 状态 | 含义 | 要不要人工处理 |
|---|---|---|
| `未处理` | 已入库还没发分 | 正常跑完不会残留 |
| `成功颁发X.X分` | APP 回了「成功1人」，**确认成功** | 不用 |
| `未找到（已报名，可能已发分或未签到）` | 在发分页搜学号搜不到 | 建议核对 |
| `姓名不符，应为A，实际为B` | APP 里搜出来的姓名和名单对不上，未发分 | 要 |
| `未知(提示:XXX)` | 点了颁发但没读到 Toast 提示 | **一定要人工核对** |
| `颁发失败（异常）` | 重试 3 次仍抛异常 | 要 |
| `设备连接失败，用户退出` | 掉线且你在重连提示里选了退出 | 要 |
| `学号错误（非11位有效学号）` | 学号不合法，预处理阶段就拦下了 | 要 |
| `未报名（或学号错误）` | 发分名单里的人不在录取名单里 | 要 |
| `姓名错误（或学号填写错误），录取表姓名X` | 姓名不一致，且你在交互里选择了拒绝 | 要 |

### 5.3 续跑

```bat
python DM.py -r "D:\path\to\daomeng\2026年春季运动会志愿服务-20260928-120000"
```

- 会读取该目录的 `config.json`，跳过 Excel 重新解析，只处理数据库里状态仍是 `未处理` 的人
- `-d` 和 `-u` 可以改（换设备、换账号），名单相关参数（`-f` / `-a` / `-yb`）不允许再传
- 续跑前建议先把手机端状态确认一下：上次可能发到一半，APP 里已经发过的人再发一次可能报错或重复

## 6. 常见问题

### 6.1 报「找不到 ADB 文件: ...\daomeng\platform-tools\adb.exe」

路径是写死的，按 [1.3](#13-准备-adb最容易踩的坑) 把 `platform-tools` 文件夹连 `adb.exe` 一起放到位。

### 6.2 `adb devices` 是空的 / 显示 `unauthorized`

- 手机上没点「允许 USB 调试」→ 重新插拔数据线，看手机弹窗
- 数据线只能充电 → 换一根
- 驱动没装（尤其小米/OPPO/vivo）→ 装厂商手机助手或 Google USB Driver
- 显示 `unauthorized` → 在手机开发者选项里点「撤销 USB 调试授权」，再重新插拔授权

### 6.3 `-i` 报 `unrecognized arguments: --device`

**不要把 `-i` 和 `-d` 一起用。** 源码在指定设备时会把命令拼成 `python -m uiautomator2 init --device <串>`，而 uiautomator2 的 `init` 子命令只认 `--serial` / `-s`（2.x 和 3.x 都是这样），所以会直接报参数错误、初始化失败后退出来。

- 想初始化：只加 `-i`、不加 `-d`（`init` 会对当前已连接的所有设备执行初始化）
- 想连无线设备：只加 `-d`、不加 `-i`

### 6.4 跑到一半报设备连接失败 / 手机端服务被杀

- 关掉该 APP 的电池优化和后台限制（设置 → 应用 → 到梦空间 → 电池 → 无限制）
- 开发者选项里打开「充电时不锁定屏幕」「保持唤醒」之类的选项
- 重试时加 `-i` 重新初始化设备端服务
- 手机锁屏了也会失败，把息屏时间调长

### 6.5 报「未找到活动: XXX」

- `活动名称` 那一格（记住是**第二行数据**）填的内容和 APP 里显示的不完全一致，注意空格、书名号、括号
- 或者这个活动不在你账号的「我的活动 / 管理」列表里，或者账号权限不够
- 脚本会自动尝试把筛选切到「已结束」，所以已结束的活动也能发分

### 6.6 一直「未识别的界面」、来回返回、最后让你手动操作

APP 改版把控件 id 改了。所有选择器都集中在 `daomeng/selectors.py` 的 `SELECTORS` 字典里，用 uiautomatorviewer 或 [uiautodev](https://github.com/uiautodev/uiautodev) 抓新的 `resourceId` 改进去即可，改完把 `_get_current()` 和 `navigation()` 里对应的界面名字也对一下。

### 6.7 状态大面积是 `未知(提示:未获取到Toast)`

脚本拿不到 APP 的 Toast 文案（没给通知权限、系统限制、或 Toast 被别的弹窗顶掉）。**这代表「命令发出去了但没确认结果」，一定要去 APP 里人工核对**这批人到底发没发。

### 6.8 日志/控制台中文乱码

- 日志文件是 UTF-8，用 VS Code / Notepad++ 打开
- 控制台建议用 **Windows Terminal**；老式 cmd 里先执行 `chcp 65001`，并把字体换成支持中文的（比如 "Cascadia Mono" / "Consolas" 配合中文回退）
- 报 `UnicodeEncodeError` 时，可先 `set PYTHONUTF8=1` 再执行

### 6.9 想彻底重来一次

新建一个输出目录就等于重来（脚本每次都会按时间戳建新目录）。只要别用 `-r` 指向旧目录即可。

## 7. 已知限制

- **只能操作一台手机**：代码里 `self.score` 是全局状态，不支持并发多设备
- **只支持安卓版「到梦空间」**：包名写死 `com.jingcai.apps.qualitydev`，只认中文界面的这套控件
- **账号表只取第一条**（`cli.py` 里标注了 `TODO: 多账号支持`）
- **学号必须是 11 位数字**，其他位数一律按无效处理（可走交互式纠正）
- **成功结束会删掉进度数据库**，所以断点续跑只在失败中断后可用
- 仓库没有 `requirements.txt`、没有 `LICENSE`、没有任何自动化测试
- UI 选择器强依赖 APP 版本，APP 一改版就可能要维护 `selectors.py`

## 8. 一分钟最小流程

```bat
:: 1. 装依赖
pip install pandas openpyxl rich uiautomator2

:: 2. 把 platform-tools 放进 daomeng\platform-tools\（里面要有 adb.exe）

daomeng\platform-tools\adb.exe devices

:: 5. 首次跑：在正式命令上加 -i（先初始化设备端服务，再照常发分）

:: 6. 之后正常跑（不用再加 -i）
python DM.py -f "D:\名单\录取名单.xlsx" 0 -f "D:\名单\发分名单.xlsx" 0.5 -u "D:\名单\账号.xlsx"

:: 7. 去 DM.py 同级的 <活动名>-<时间戳>\ 目录看结果表和日志
```

## 9. 安全与合规

- **明文密码**：`config.json` 里以明文保存账号密码，且**任务失败时不会自动删除**。跑完（尤其是失败后）请把输出目录里的 `config.json` 删掉，不要把目录发给别人或传到网盘
- **账号风险**：这是用真实账号在真实业务系统上做高频模拟点击，存在被平台风控、限制登录的可能
- **权限与规定**：请只在你本人有管理权限的活动上使用，并遵守学校与「到梦空间」平台的相关规定。批量发分是敏感操作，发错很难撤回
- **先小范围验证**：建议先用 2~3 人的名单在测试活动上跑通，再上真实名单

## 10. 代码结构

| 文件 | 行数 | 职责 |
|---|---|---|
| `DM.py` | 18 | 程序入口，捕获 `Ctrl-C` 和未处理异常 |

| `daomeng/file_manager.py` | 1310 | Excel 读取与校验、学号提取（`_extract_student_id`）、交互式纠错、SQLite 持久化、导出结果 |

改代码时的几个约定：

- 学号规则在 `file_manager.py::_extract_student_id()`（正则 `(?<!\d)\d{11}(?!\d)`）

- 日志一律用 `self._logger`，用户交互用 `rich.Console()`，不要 `print`
